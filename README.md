# LoveAgain — 다시, 사랑

돌싱(이혼·사별 후 재혼을 원하는 싱글)을 위한 진지한 매칭 앱.

---

## 기능 스펙

### 핵심 기능

#### 1. 회원가입 및 인증
- 본인 인증 필수 (휴대폰 인증)
- 이혼확인서 또는 사망진단서 등록 (심사 후 인증 뱃지 부여, 48시간 이내)
- 허위 서류 등록 시 영구 차단

#### 2. 프로필
- 기본 정보: 이름(실명), 나이, 지역, 직업, 키, 종교, 흡연·음주 여부
- 자녀 현황: 자녀 수, 나이, 동거 여부
- 이혼/사별 후 경과 기간
- 재혼 의향 (진지한 만남 / 재혼 희망 / 천천히 알아가기)
- 자기소개 (최대 500자)
- 관심사 태그 (최대 5개)
- 사진 등록 (최대 6장, AI 얼굴 인증 필수)

#### 3. 매칭 탐색

**추천 주기**
- **3시간마다** 새로운 추천 5명 갱신 (이전: 하루 1회)
- 3시간 내 카드를 모두 소진하면 다음 갱신까지 카운트다운 표시
- 추가 추천은 티켓 사용

**카드 액션 (버튼 3종)**
| 버튼 | 동작 |
|------|------|
| ✕ 패스 | 카드 영구 제거. 추천에 다시 나올 때까지 재탐색 불가 |
| 보류 | 카드를 보류함에 저장. 메시지탭 > 보류 중에서 나중에 다시 결정 가능 |
| 💝 좋아요 | 3일간 채팅 채널 개설. 상대방도 좋아요 시 매칭 성사 |

- 슈퍼좋아요(⭐) 제거

**보류함**
- 보류한 프로필은 메시지 탭 > 보류 중 섹션에 보관
- 보류함에서 좋아요 또는 패스로 최종 결정
- 결정 전까지 무기한 보류 가능

#### 4. 사업화: 추가 추천 티켓
- 기본 제공: **3시간당 5명** 무료 추천
- 추가 추천: **티켓 1개당 1명** 추가 추천 소모
- 티켓 구성:
  - 티켓  10개:    900원 (90원/개)  
  - 티켓 100개:  7,900원 (79원/개)  
  - 티켓 200개: 12,000원 (60원/개)  

#### 5. 3일 채팅 & Save / Throw

**핵심 메카닉**
- 💝 좋아요를 누르면 **3일간 채팅 채널**이 개설됨
- 채팅방 헤더에 남은 기간 표시 (D-3 → D-2 → D-1 → D-0)
- 3일이 지나면 **Save 또는 Throw** 선택 팝업 노출

| 선택 | 결과 |
|------|------|
| **Save** | 채팅 기간 무제한 연장. 이후 자유롭게 대화 지속 |
| **Throw** | 채팅방 영구 삭제. 상대방을 다시 찾을 방법 없음. 추천에서 다시 뜰 때까지 재연결 불가 |

- 상대방도 같은 선택을 하며, 한쪽이라도 Throw하면 채팅방 삭제

#### 6. 메시지
- 매칭 성사 후 채팅 잠금 해제
- **첫 편지 기능**: 첫 메시지는 최소 50자 이상 (진지한 대화 유도)
- 이후 자유 채팅
- 사진 전송 가능 (매칭 후 24시간 이후부터)

#### 6. 안전·신고
- 메시지 AI 모니터링 (욕설, 성적 표현, 불법 콘텐츠 자동 차단)
- 1회 경고 → 3일 정지 → 영구 차단
- 신고 센터 (24시간 대응)
- 차단 기능

#### 7. 커뮤니티 (v2 예정)
- 돌싱 라이프 정보 공유 게시판
- 지역별 소모임 (오프라인 연계)

## 취향 분석 시스템

사용자의 탐색 행동(패스·보류·3일채팅·Save·Throw)을 누적해 개인화 추천 품질을 개선한다.

---

### 수집 데이터 설계

#### 이벤트 및 신호 강도

| 이벤트 | 가중치 | 해석 |
|--------|--------|------|
| Save | +3 | 대화 연장 — 가장 강한 긍정 신호 |
| 3일 채팅 (좋아요) | +2 | 긍정 신호 |
| 보류 | +0.5 | 약한 긍정 · 판단 유보 |
| Throw | -1 | 대화 후 부정 (더 무거운 신호) |
| 패스 | -2 | 명확한 거절 |

> Save와 Throw는 단순 스와이프보다 강한 신호다. 대화를 실제로 경험한 뒤 내린 결정이기 때문이다.

#### 저장 스키마 (TypeScript 기준)

```ts
interface UserAction {
  userId: string;
  targetProfileId: string;
  action: "pass" | "hold" | "like" | "save" | "throw";
  timestamp: string; // ISO 8601

  // 결정 시점의 상대 프로필 스냅샷
  // (프로필 수정 이력에 무관하게 결정 당시 상태를 보존)
  snapshot: {
    age: number;
    location: string;
    jobCategory: string;   // 직군 분류 (예: "전문직", "자영업", "사무직")
    kids: "없음" | "있음·비동거" | "있음·동거";
    intent: "재혼희망" | "진지한만남" | "천천히알아가기";
    tags: string[];        // 관심사 태그 최대 5개
    religion?: string;
    smoking: boolean;
    drinking: "안함" | "가끔" | "자주";
  };
}
```

**스냅샷을 저장하는 이유**: 상대방이 프로필을 수정하더라도, 사용자가 실제로 보고 판단한 시점의 데이터를 기준으로 취향을 분석해야 한다.

---

### 취향 분석 로직 로드맵

#### Phase 1 — 속성별 빈도 집계 `(즉시 적용 가능 · 데이터 30건~)`

각 속성 카테고리별로 긍정 액션(like·save) 비율을 집계해 **선호 프로파일**을 생성한다.

```
likeRateByAgeGroup:    { "35-39": 0.80, "40-44": 0.60, "45-49": 0.20 }
likeRateByLocation:    { "서울": 0.75, "경기": 0.50, "부산": 0.20 }
likeRateByKids:        { "없음": 0.70, "있음·비동거": 0.40, "있음·동거": 0.15 }
tagAffinityScore:      { "여행": 1.4, "독서": 1.1, "골프": 0.3 }
```

→ 추천 시 각 속성 점수의 **가중 평균**으로 후보 프로필을 정렬해 상위 5명을 노출한다.

#### Phase 2 — 시간 감쇠 가중 점수 모델 `(데이터 300건~)`

- 액션별 가중치(Phase 1 표 참고)를 속성별로 **누적 합산**
- **Exponential decay** 적용: 최근 행동일수록 더 높은 가중치 부여 (`score × e^(-λt)`)
  - 취향은 시간에 따라 변할 수 있음 (예: 초반엔 자녀 없음 선호 → 수개월 후 재고)
- 속성 카테고리별로 정규화해 한 속성(예: 지역)이 전체 점수를 지배하는 것을 방지

#### Phase 3 — 협업 필터링 + 콘텐츠 기반 하이브리드 `(데이터 10만 건~)`

- **협업 필터링**: 유사한 행동 패턴을 가진 사용자 군집화 → 군집 내 높은 평가를 받은 프로필 추천
  - 알고리즘: ALS(Alternating Least Squares) 기반 Matrix Factorization
- **콘텐츠 기반 필터링**: 긍정 반응 프로필의 속성 벡터 → 코사인 유사도로 유사 프로필 검색
- **두 점수를 혼합** (예: 0.6 × 협업 + 0.4 × 콘텐츠)해 Cold Start와 Popularity Bias 보완
- 매 스와이프 후 실시간으로 추천 목록 재랭킹

---

### Cold Start 전략

신규 가입자는 행동 데이터가 없어 개인화가 불가능하다.

| 단계 | 방법 |
|------|------|
| **0건** | 온보딩 서베이 결과(선호 연령대·지역·자녀 여부)를 초기 선호 프로파일로 시딩 |
| **1~29건** | 같은 성별·연령대·지역 사용자 군집의 평균 선호 패턴 사용 (인구통계 기반) |
| **30건~** | 개인 행동 데이터로 Phase 1 분석 시작 |
| **300건~** | Phase 2 모델로 자동 전환 |

---

### 개인정보 및 윤리 고려사항

- **비공개 원칙**: 행동 로그는 추천 개선 목적으로만 사용. 상대방에게 "이 사람이 당신을 보류했습니다" 형태로 노출 금지.
- **데이터 보존**: 탈퇴 시 행동 로그 즉시 삭제 또는 익명화 처리. 보존 기간 이용약관 명시 필요.
- **동의 기반 수집**: 개인정보보호법·GDPR 준수. 수집 목적·항목·보유 기간 고지 및 동의 확보.
- **편향 방지**: 특정 속성(나이·직업·지역)에 점수가 과도하게 집중되지 않도록 속성별 점수 상한 설정 권장.
